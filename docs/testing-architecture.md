# Testing Architecture

This document explains how the tests of the AI Engineering Bazaar reader are structured, bootstrapped and written.
Read it before adding a test.

## Philosophy

- **Mirror the source tree.** `test/` mirrors `lib/`, so the test of any file is where you expect it.
- **Mock at the boundary, not the wire.** Bloc and widget tests mock the repository interface or the bloc with `mocktail`; only the repository tests reach HTTP, through `MockClient`.
- **One global bootstrap.** Cross-cutting setup (binding, logger, fallback values, per-test reset) lives in one place; a test file holds only what is its own.
- **Sealed states, exhaustive matching.** Bloc tests assert on sealed state variants (see `CLAUDE.md`, State Modeling).
- **Determinism.** No test depends on wall-clock time, on order, or on state leaked from another test.
- **No course facts.** Tests read the synthetic fixture under `test/fixtures/content/`, never a module key or title of the real course (spec 3.11).

## Test stack

| Tool | Purpose |
| --- | --- |
| `flutter_test` | Test runner, `WidgetTester`, matchers |
| `bloc_test` | `blocTest(...)` and `MockBloc` for bloc and cubit state assertions |
| `mocktail` | Mocks and fakes without code generation (`Mock`, `Fake`, `when`, `verify`, `any`) |
| `package:http/testing.dart` | `MockClient` for the content requests |
| `fake_async` | Virtual time for timers, such as the undo window |
| `alchemist` | Golden tests |
| `integration_test` | Device tests under `integration_test/` |

`mocktail` is the single mocking library; there is no `mockito` and no `build_runner`.

## The global bootstrap

`flutter test` discovers `test/flutter_test_config.dart` and wraps every test under `test/` with its `testExecutable`:

```dart
Future<void> testExecutable(FutureOr<void> Function() testMain) async {
  // One-time per isolate.
  TestWidgetsFlutterBinding.ensureInitialized();
  AutomatedTestWidgetsFlutterBinding.instance.defaultTestTimeout = const Timeout.factor(1); // see "Timeouts"
  AppLogger.configure(isProduction: false, logFormat: LogFormat.simple);
  EquatableConfig.stringify = true;
  registerAllFallbackValues();

  // Per-test in every file, opted out or not (see "The asset cache").
  setUp(rootBundle.clear);
  tearDown(rootBundle.clear);

  // Per-test, unless a file opts out.
  setUp(() async { if (TestEnv.autoReset) await TestEnv.reset(); });
  tearDown(() async { if (TestEnv.autoReset) await TestEnv.reset(); });

  // Goldens render under the light bazaarTheme (Android); platform goldens are off.
  return AlchemistConfig.runWithConfig(config: ..., run: testMain);
}
```

A test file needs no setup for the logger, the binding or the fallback values.

### `TestEnv` (`test/support/test_env.dart`)

| Member | Use |
| --- | --- |
| `TestEnv.reset()` | Clears the process-wide `DevConsoleStore.instance` and `TimeTravelStore.instance`. Idempotent and in memory; the bootstrap calls it before and after every test. |
| `TestEnv.autoReset` | Set `false` in a file's `setUpAll` to opt that file out of the global reset. |

`flutter test` runs each file in its own isolate, so opting out in one file cannot reach another.
A file's `setUpAll` runs after the bootstrap registered the global `setUp` and before the first test's `setUp`, so the flag is read in time.

### Opting out

A file that installs its own `MethodChannel` handler, or needs state to survive between its tests, opts out:

```dart
void main() {
  setUpAll(() => TestEnv.autoReset = false); // first thing in main()
  // ... the file manages its own setUp and tearDown ...
}
```

Golden files opt out this way, as `test/shared/design_system/components/app_button_golden_test.dart` does.
A mock on a channel the reset never touches needs no opt-out: `test/support/url_launcher_stub.dart` installs one for url_launcher in the test body and removes it when the test ends.

### The asset cache

`rootBundle` caches the `Future` of every string asset it loads, such as a file of the bundled snapshot under `assets/content/`.
Code that awaits a cached `Future` is resumed by a microtask of the zone that created it.
Each `testWidgets` body runs in its own `FakeAsync` zone, and nothing runs that zone's microtasks once the test ends.
So once a `testWidgets` had loaded a snapshot file, every later `testWidgets` of the same file that needed it waited forever.
The bootstrap therefore empties the cache with `rootBundle.clear()` before and after every test, in every file, including the files that opt out of `TestEnv.reset()`.
`test/support/test_env_test.dart` and `test/flutter_test_config_test.dart` guard this.
Tests that read the synthetic snapshot through `FixtureAssetBundle` (`test/support/content_fixture.dart`) read its files synchronously, so they need no `runAsync`.

### Timeouts

Every test, `testWidgets` included, times out after the 30 seconds of `dart_test.yaml`, or twice that in a file tagged `@Tags(['integration'])`.
On its own, `testWidgets` passes the binding's `defaultTestTimeout` of 10 minutes to `test()`, and a test's own duration replaces the configured timeout, so a hung widget test held CI for 10 minutes.
The bootstrap sets `defaultTestTimeout` to `Timeout.factor(1)`, which keeps the configured timeout, and `test/flutter_test_config_test.dart` guards it.
A test that needs longer gets its own timeout with a reason, as `integration_test/app_test.dart` has `@Timeout(Duration(minutes: 5))` for the device test that opens every module in both tracks, instead of a higher timeout for everyone.

## Writing each kind of test

### Bloc and cubit tests: `blocTest` and sealed states

Mock the repository interface and assert the exact states:

```dart
blocTest<ContentBloc, ContentState>(
  'starts, opens, then refreshes once',
  setUp: () {
    opens();
    when(() => repository.refresh()).thenAnswer((_) async => const ContentUpToDate());
  },
  build: () => ContentBloc(repository: repository),
  act: (bloc) => bloc.add(const ContentStarted()),
  expect: () => [ready(const RefreshIdle()), ready(const RefreshChecking()), ready(const RefreshUpToDate())],
  verify: (_) => verify(() => repository.refresh()).called(1),
);
```

- Assert on sealed variants (`ContentReady`, `ContentBroken`, `RecordReady`), not on a status field.
- `RecordBloc` tests (`test/shared/record/application/record_bloc_test.dart`) drive the writes, the erase and its 10 s undo window with `fakeAsync`, never with a real delay.
- `MockBloc` (`MockContentBloc` and `MockRecordBloc` in `test/support/bazaar_app_harness.dart`, `MockDataBloc` and `MockModuleReaderBloc` in `test/mocks/mock_classes.dart`) feeds a widget test a scripted state stream.

### Repository tests: a temp directory and `MockClient`

`FileRecordRepository` takes its base directory and `FileContentRepository` its cache directory as a function, so a test hands them a fresh temp directory and deletes it after:

```dart
setUp(() {
  base = Directory.systemTemp.createTempSync('record_repo_test_');
  repo = FileRecordRepository(baseDirectory: () async => base);
});
tearDown(() => base.deleteSync(recursive: true));
```

A content refresh goes through a `MockClient` that serves the synthetic bundle's files (`test/support/content_refresh_cases.dart`, `test/infrastructure/content/file_content_repository_refresh_test.dart`), so no test reaches the network.

### Widget tests: mocked blocs over the synthetic fixture

- Content comes from the synthetic fixture: `alpha/first` is written in both tracks with one block of every type, `alpha/second` is For Engineers only, `beta/third` is planned (`test/fixtures/content/README.md`).
- `test/support/content_fixture.dart` provides `FixtureAppDependencies` (a ready content repository over the fixture and a record repository with no record), `FixtureAssetBundle` and `testContentBaseUrl` (`https://content.test/`), so an expected web URL in a test reads `https://content.test/...`.
- `bazaarTestApp` and `pumpUntilFound` (`test/support/bazaar_app_harness.dart`) mount a page under the router with the blocs a test passes; `pumpBlocks` (`test/support/content_builders.dart`) mounts content blocks alone.
- Verify an action by its event type and an explicit count, `verify(() => recordBloc.add(any(that: isA<RecordReplaced>()))).called(1)`, never `add(any())`: a page adds an event on mount, so a loose verify passes even when the action never fired.
- Size the surface with `tester.view.physicalSize` and `addTearDown(tester.view.reset)`; assert navigation by what the destination renders.

### End-to-end smoke

`test/integration/app_smoke_test.dart` boots the whole `App` over the fixture dependencies, with the content store and the record files in a temp directory: a cold start shows the catalog with no sign-in, and a completion survives a restart.
It is a full-app widget test, so it runs headless under `flutter test`.

### Device tests

`integration_test/app_test.dart` runs the real app on an emulator, a simulator or a phone, with the bundled snapshot and a content base URL that refuses every connection, so the app is offline:

- it boots offline from the bundled snapshot to the catalog;
- a written module opens and renders its first heading;
- every module with an English document opens as written or planned, in both tracks;
- a completion persists after the app is rebuilt over the same directory.

The device tests start `App` without the bootstrap and without `test/flutter_test_config.dart`, so `pumpDeviceApp` (`integration_test/support/device_app.dart`) configures the logger itself.
Run them locally through `heavy`, with the emulator started and airplane mode on after boot:

```shell
adb shell cmd connectivity airplane-mode enable
heavy fvm flutter test integration_test -d emulator-5554 --reporter expanded
```

The `Device tests` workflow (`.github/workflows/device_tests.yml`) runs them on an Android emulator and an iOS simulator when it is dispatched.

### Conformance and contract tests

- `test/shared/record/conformance_test.dart` replays `test/fixtures/record_conformance/v1.json`, the web's record conformance fixture, the way the web's `tests/unit/record/conformance.test.ts` drives it: the constants, then the `parse`, `reduce`, `export` and `derive` cases.
  The fixture is generated by `tool/refresh_content_snapshot.dart` and never edited; the test is the authority on the record format.
  Each of these mutations of the port fails it, or the clock test of `test/shared/record/domain/instant_test.dart`: a `nowIso` that keeps microseconds, a writer that sorts map keys, an unsign that stamps a day, a schema rule without `isFinite`.
- `test/architecture/content_snapshot_contract_test.dart` holds the bundled snapshot to the contract: every object is named by its sha256, every document parses, every diagram follows the web's SVG profile and draws one text command per label, and every SVG and every raster figure decodes (A44).

## Mocks and fakes

- **mocktail mock (default):** the `Mock*` classes in `test/mocks/mock_classes.dart` (`MockContentRepository`, `MockRecordRepository`, `MockBackupGateway`, `MockDataBloc`, `MockModuleReaderBloc`), configured with `when(...)` and checked with `verify(...)`.
  `registerAllFallbackValues()` registers every fallback once; the bootstrap calls it.
- **hand-written fake:** a private `_Fake*` or `_Memory*` class next to the test when the double needs real stateful behaviour: an in-memory store, a throw on the Nth call, sequenced failures.
  These are purpose-built per test; two same-named fakes in different files are not duplication.
- **`MockClient`** for HTTP: a content test answers each request from the synthetic bundle or with the failure it is about.

## Architecture and guard tests

`test/architecture/` holds the meta-tests that fail the build when a rule is broken:

- `android_manifest_test`: the main manifest declares `INTERNET`, and OS backup and device transfer include the record directory (`files/record/`) and nothing else.
- `app_identity_test`: application id `dev.lokumai.bazaar`, launcher label "Bazaar", the Kotlin package and the native Sentry channel named after the id on both sides.
- `arb_copy_register_test`: every message of `intl_en.arb` follows the web's copy register (A12).
- `arb_keys_used_test`: every message of the template ARB is read by some file under `lib/`.
- `arb_translations_test`: every other ARB file has the template's messages and placeholders (vacuous while English is the only language).
- `bundled_snapshot_assets_test`: the bundled snapshot is declared as assets.
- `content_facts_not_restated_test`: no string literal in `lib/`, `test/` or `integration_test/` restates a fact of the course (spec 3.11).
- `content_snapshot_contract_test`: the bundled snapshot holds the contract (see "Conformance and contract tests").
- `dependencies_used_test`: every dependency in `pubspec.yaml` has an importer, apart from a listed few with their reasons.
- `docs_current_test`: the docs carry no em or en dash, name no removed template code, and this file names every guard.
- `import_guard_test`: the layering rules of `CLAUDE.md`, the domain folders of the two kernels free of Flutter and I/O, and url_launcher only behind `lib/shared/utils/external_link.dart`.
- `log_lazy_arguments_test`: no `AppLogger` argument builds its text before the call.
- `log_placeholders_test`: every `AppLogger` call has one `{}` per argument.
- `log_secrets_test`: no `AppLogger` argument names a credential.
- `package_name_test`: the package is `ai_engineering_bazaar` and nothing imports the template's package.
- `platform_folders_test`: only `android/` and `ios/` exist, and iOS uses no CocoaPods.
- `route_telemetry_test`: no code records a route for analytics or Sentry, since a route path carries a module key.
- `sentry_native_scrub_patterns_test`: the Kotlin scrub patterns of the Android host equal the Dart ones, and the Gradle DSN gate holds.
- `test_file_naming_test`: no test file is named `*.test.dart`, which `flutter test` would never run.
- `tokens_generated_test`: `lib/shared/design_system/bazaar_tokens.g.dart` equals a fresh run of the token generator over the snapshot.
- `ui_text_localized_test`: widgets in `lib/` show text through `S`, not string literals.

## Accessibility

`test/support/accessibility.dart` (Task 6.3, A28) holds the checks every page runs:

- `bazaarPlatforms`: the variant of Android and iOS; a guideline test runs `testWidgets(..., variant: bazaarPlatforms, ...)` and pumps its app with `platform: defaultTargetPlatform`.
- `expectPlatformGuidelines(tester, platform: defaultTargetPlatform)`: the tap-target guideline of the platform (48 on Android, 44 on iOS, each under its own platform because Flutter's guidelines ignore it), then the labelled tap-target and text contrast guidelines, on the tree already pumped.
- `pumpAtTextScale(tester, app, scale: 2.0)`: a 390x844 surface at the given text scale (3.0 for the reader), reset when the test ends.
- `expectHittable(tester, finder)`: a tap at the widget's centre reaches it.

## Goldens

Golden tests use `alchemist` and live next to the code they cover, with their images in a sibling `goldens/ci/` folder.
Screens render at 390x844 (`kGoldenScreenSize`, `goldenScreen` in `test/support/golden_app.dart`), light and dark.
The bootstrap turns platform goldens off, so only the CI variant runs, with Ahem text, the same on every host.
There are 32 golden images (`find test -path '*goldens/ci/*.png' | wc -l`).
Regenerate them after an intended visual change, through `heavy`:

```shell
heavy fvm flutter test --tags golden --update-goldens
```

## Determinism

- **Time:** use `fakeAsync` for timers and `withClock(Clock.fixed(...))` of `package:clock` for instants; never `DateTime.now()` in a test.
- **Mocked async:** do not use `blocTest(wait:)` to let a mock settle; sequence dependent events with `await bloc.stream.firstWhere(...)`.
- **Tags:** `dart_test.yaml` declares `widget`, `golden` (applied by alchemist) and `integration`; slice with `fvm flutter test --tags widget` or `--exclude-tags widget`.
- **Pumping:** `pumpAndSettle()` only when every animation finishes; its `Duration` argument is the interval between pumps, not a timeout.
  For a spinner or any looping animation use `pump(Duration)`; in goldens use `pumpBeforeTest: pumpOnce`.

## Coverage

`scripts/check_coverage.sh` computes line coverage without generated and bootstrap code (`lib/generated/**`, `*.g.dart`, `lib/main/main_*.dart` and the like); the floor is 65 %.

## Running tests

```shell
fvm flutter test                                   # the whole suite
fvm flutter test test/features/reader              # a subtree
fvm flutter test test/path/to/specific_test.dart   # one file
```

A single file needs nothing more; the whole suite and every gate run through `heavy`, one full gate at a time.
The gate every commit passes:

```shell
heavy bash -c 'fvm dart format . --line-length=120 --set-exit-if-changed && fvm flutter analyze && fvm flutter test --coverage && scripts/check_coverage.sh coverage/lcov.info 65'
```

The Android JVM unit tests (`android/app/src/test/kotlin`) cover the Kotlin scrubber of native Sentry events and run in the Android job of CI.
They need JDK 17 and the Gradle wrapper, which is not committed: any Flutter Android build writes it, for example `fvm flutter build apk --config-only --target lib/main/main_prod.dart`.

```shell
cd android && ./gradlew :app:testDebugUnitTest -Ptarget=lib/main/main_prod.dart
```

## Adding tests for a new feature

1. Create `test/features/<feature>/` mirroring the feature's folders under `lib/`.
2. Bloc or cubit tests (`application/`): `blocTest` over a mocked repository or a mocked shared bloc; assert sealed variants.
3. Repository tests, if the feature brings infrastructure: a temp directory and `MockClient`, never the network or the real course.
4. Widget tests (`presentation/`): `MockBloc` for state, content from the synthetic fixture through `FixtureAppDependencies` or `pumpBlocks`, URLs under `testContentBaseUrl`.
5. Every page: `expectPlatformGuidelines` under `bazaarPlatforms` and `pumpAtTextScale` at 2.0.
6. Add a new shared mock to `test/mocks/mock_classes.dart`, and its fallback to `registerAllFallbackValues()` when a test uses `any()` with a new non-nullable type.
7. Do not add per-file binding, logger or reset setup; opt out with `TestEnv.autoReset = false` only when the file installs its own channel mock.
